# ISSUE 템플릿

**발견된 문제.** 지금 못 고치거나 추적이 필요할 때만 만든다.

`status`: `open` → `done`(해결) → `dropped`(재현 안 됨·안 고치기로 함)

```markdown
---
id: ISSUE-0001
title: <증상을 한 문장. 원인 추측을 제목에 넣지 않는다>
status: open
links: []
updated: <YYYY-MM-DD>
---

## 증상
<관찰된 것. 기대와 실제>

## 재현
```
<최소 절차. 재현 못 하면 그렇다고 적는다>
```

## 영향
<무엇이 안 되나. 얼마나 자주. 우회 가능한가>

## 원인
<아는 만큼만. 모르면 "미확인">

## 임시 조치
<지금 적용한 우회. 없으면 "없음">

## 해결 경로
<어느 TASK·ADR 로 이어지나>
```

## 규칙
- **지금 고칠 수 있으면 문서를 만들지 않고 고친다.** ISSUE 는 미룰 때의 수단이다
- 제목에 원인을 쓰지 않는다. 추측이 제목에 박히면 다른 원인을 안 본다
- 재현 절차가 없는 ISSUE 는 닫을 수 없다. 못 만들었으면 "재현 미확립" 이라고 적는다
- 해결되면 `done` 으로 바꾸고 남긴다. 지우면 같은 문제가 처음 보는 문제가 된다
