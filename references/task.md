# TASK 템플릿

**한 단위 작업.** 브랜치 1개에 대응한다 (`/branch-policy` 2절).

`status`: `open` → `done` → `dropped`(안 하기로 함)

```markdown
---
id: TASK-0001
title: <무엇을 한다. 동사로>
status: open
links: [REQ-0001, ARCH-0001]
updated: <YYYY-MM-DD>
---

## 목표
<한 문장. 브랜치 이름과 커밋 메시지가 여기서 나온다>

## 완료 조건
- [ ] <무엇이 참이면 끝인가. 검증 가능한 것만>

## 건드리는 곳
<파일·모듈. 저장소 상대경로>

## 위험
<깨질 수 있는 것. 없으면 "없음">
```

## 규칙
- **PR 본문과 중복하지 않는다.** TASK 는 *계획*, PR 본문은 *진행 상태*
  (`/task-policy` 4절). 같은 내용을 두 곳에 쓰면 한쪽이 낡는다
- 작은 작업은 TASK 문서를 만들지 않는다. PR 하나로 끝나고 설명이 필요없으면 그게 맞다
- 완료 조건이 체크박스로 안 떨어지면 작업이 너무 크다. 쪼갠다
- 브랜치 type 은 `/branch-policy` 1절의 넷. TASK 가 그 type 을 정한다
