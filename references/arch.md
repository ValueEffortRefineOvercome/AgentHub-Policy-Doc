# ARCH 템플릿

**어떻게 만드나** — 구성요소, 경계, 흐름. 대안 비교는 ADR 로 분리한다.

`status`: `draft` → `done`(이대로 만든다) → `dropped`(폐기)

```markdown
---
id: ARCH-0001
title: <구조를 한 문장으로>
status: draft
links: [REQ-0001]
updated: <YYYY-MM-DD>
---

## 구성요소
| 이름 | 책임 | 하지 않는 것 |
|---|---|---|

## 경계
<무엇이 무엇을 모르는가. 의존 방향>

## 흐름
<주요 경로 1~2개. 요청이 들어와 나가기까지>

## 제약
<이 구조가 전제하는 것. 깨지면 구조를 다시 봐야 하는 것>

## 설계 결정
- <ADR-NNNN> — <한 줄>
```

## 규칙
- **"하지 않는 것" 열을 비우지 않는다.** 책임만 적으면 경계가 생기지 않는다
- 대안을 여기서 비교하지 않는다. 비싼 선택은 ADR 을 만들고 링크만 남긴다
- 다이어그램은 글로 먼저 쓴 다음에. 글로 못 쓰는 구조는 그림으로도 안 된다
